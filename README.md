# NoteNest

A local-first notes and lists app for **Windows and Android**, built in Flutter.
Everything is stored on your device first and works with no internet. A
**private GitHub repository** is used only for sync and backup — there is no
server and no account to create.

```text
Windows local SQLite  <--->  private GitHub repo  <--->  Android local SQLite
```

---

## Setup (one time)

**Any Flutter 3.22 or newer works, including the current stable.** The
easiest way to install it is to let VS Code do it: install the
[Flutter extension](https://marketplace.visualstudio.com/items?itemName=Dart-Code.flutter),
open the command palette, run **Flutter: New Project**, and choose
**Download SDK** — it sets up the PATH for you. Manual instructions are at
[docs.flutter.dev/install/manual](https://docs.flutter.dev/install/manual).

For Android builds you also need Android Studio or the Android SDK; for the
Windows desktop build you need the Visual Studio 2022 Build Tools with
"Desktop development with C++". Neither is needed to run the tests.

The repository holds the **app source only**. The `android/` and `windows/`
runner folders are generated by Flutter, so the first step creates them:

**Windows (PowerShell, from the repository root):**

```powershell
powershell -ExecutionPolicy Bypass -File tool\setup.ps1
```

**Linux/macOS:**

```bash
bash tool/setup.sh
```

The script runs `flutter create` for Windows + Android, restores the NoteNest
source over Flutter's templates, adds the Android INTERNET permission, fetches
packages, generates the Drift database code and the launcher icons, then
analyzes and tests.

If you prefer to do it by hand:

```bash
flutter create . --project-name notenest --org com.notenest --platforms=windows,android
git checkout -- lib pubspec.yaml analysis_options.yaml test   # undo template overwrites
flutter pub get
dart run build_runner build --delete-conflicting-outputs      # REQUIRED: generates database.g.dart
dart run flutter_launcher_icons                              # REQUIRED: app icon (Windows + Android)
cp assets/icon/app_icon.ico windows/runner/resources/app_icon.ico   # multi-size Windows icon
flutter analyze
flutter test
```

> `dart run build_runner build` is not optional. Drift generates
> `lib/data/db/database.g.dart` from the table definitions, and the app will
> not compile until it exists.

## App icon

The launcher icon (an "N" monogram of pastel sticky-note bars on the brand
blue) lives in `assets/icon/`:

- `app_icon.png` — 1024×1024 master used for every platform
- `app_icon_adaptive_fg.png` — Android adaptive-icon foreground (monogram
  pre-scaled into the 66% safe zone)
- `app_icon.ico` — multi-size Windows icon (16→256 px) copied over the
  generated one so the taskbar/Start icon stays crisp

`flutter create` regenerates the `windows/` and `android/` folders with
Flutter's default icons, so re-run `dart run flutter_launcher_icons` (or the
setup script) after recreating them.

## Setting up sync

1. On GitHub, create a **private** repository (for example `NoteNest`).
2. Create a **fine-grained personal access token**:
   Settings → Developer settings → Personal access tokens → Fine-grained tokens
   - Repository access: **only** your notes repository
   - Repository permissions: **Contents: Read and write**, **Metadata: Read**
3. In NoteNest: Settings → GitHub sync → enter owner, repository, branch, paste
   the token → **Test connection** → **Save and enable**.

The app refuses to enable sync on a public repository, and the token is stored
in Windows Credential Manager / the Android Keystore — never in the database,
never in a file, never in a log.

### What the repository looks like

```text
notes/<entry-id>.md              one Markdown file per note or list
images/<image-id>.jpg
thumbnails/<image-id>.jpg
.tombstones/entries/<id>.json    delete records
backups/{weekly,monthly,manual}/
```

Notes are plain Markdown with YAML front matter, so they stay readable on
github.com and recoverable without the app.

## How deletes stay deleted

The hardest part of a multi-device local-first app is stopping a deleted note
from being resurrected by a device that was offline when you deleted it.
NoteNest handles this with tombstones:

- every permanent delete writes a tombstone before anything is destroyed
- **sync always fetches tombstones before pushing anything**
- a tombstone beats the note file, the local row and the images
- a tombstoned id is never uploaded again — proven by a test that checks all
  32 input combinations of the sync decision table
- if a device edited that note while offline, the work is kept as a **new**
  recovered copy rather than resurrecting the original id

Conflicts are never merged and never overwritten: both versions are kept and
one is clearly labelled as a conflict copy.

## Project layout

```text
lib/
  app/          shell, theme, icons, colour picker, service wiring
  core/         ULID, time, hashing, crypto, redacting logger
  data/
    db/         Drift schema (entries, checklist_items, images, tombstones, ...)
    models/     enums
    repositories/  entry repository, checklist matcher, settings, secure store
  features/
    home/       card grid, search, filters, selection
    item/       View/Edit modes, checklist, images, links
    export/     PDF + TXT export
    backup/     zip snapshots, optional encryption, Markdown folder import
    settings/   appearance, sync, backup, about
    sync/       GitHub client, file codec, decision table, sync engine
test/           checklist matcher, sync decision table, file codec, core
```

## Privacy lock

Settings → PIN lock. A 4-digit PIN can hide notes, lists, or both on **this
device only**. Archive and Trash stay open. After unlock the section auto-locks
in 1, 5 or 15 minutes. Closing the app locks at once; leaving it in the
phone background keeps it unlocked until the timer ends.

On Android, a note or list in View Mode has a sun icon that keeps the screen
awake while you read.

The top sync cloud spins while a sync is running.

## Notes and limitations

- **PDF fonts.** PDF export uses a built-in Latin font offline. For Bengali,
  Hindi, Arabic or CJK text in exported PDFs, drop
  `NotoSans-Regular.ttf` and `NotoSans-Bold.ttf` into `assets/fonts/`, declare
  them in `pubspec.yaml`, and NoteNest will pick them up automatically.
  On-screen text is unaffected — only PDF export.
- **Restore from backup** is not in v1. Backups are recovery archives; unzip
  one and re-import through Settings → Markdown folder if you ever need it.
- **Encryption.** Backups can be encrypted (AES-256-GCM, PBKDF2, off by
  default). Note bodies sync as plain Markdown unless you turn on encrypted
  sync in Settings, which trades readability on github.com for privacy.
- Deleting content removes it from the app and the latest files, but old
  content can remain in the Git commit history.
